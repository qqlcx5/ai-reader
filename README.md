# 📄 产品需求文档 (PRD)：AI Reader 浏览器扩展

**版本**: v2.0 (全功能融合版)
**架构栈**: WXT + Vue 3 + Pinia + UnoCSS
**核心亮点**: 三层降级正文提取 + 多模型 SSE 并排流式输出 + 进阶自动化工作流（模型链/角色圆桌/RSS静默总结）。

---

## 模块一：内容提取与上下文 (Content Extraction)

*   **三层级联降级策略**（确保任何网页都不翻车）：
    1.  **首选**：`defuddle` 异步智能解析并转为 Markdown（设 8 秒超时限制）。
    2.  **回退**：异步失败时，尝试 `defuddle` 同步解析。
    3.  **兜底**：去除 DOM 中的 `<script>` 和 `<style>` 标签后，直接提取 `innerText` 纯文本。
*   **元数据捕获**：提取结果必须包含：文章标题、URL、正文内容、精准的字数统计。
*   **Stale 过期检测**：提取内容在内存驻留超过 **5 分钟**，UI 标记为“已过期(Stale)”，提示用户重新抓取。

---

## 模块二：核心 AI 引擎 (AI Engine & Processing)

### 1. 多模型并排对比（核心基础）
*   用户启用多个 Provider 后，点击 Run，**并发**向所有模型发送相同 Prompt。
*   基于 SSE (Server-Sent Events) 实现**独立卡片、实时逐字流式输出**。
*   **卡片网格布局**：1个模型单列，2-4个双列，>4个横向滚动。
*   **卡片级控制与数据**：
    *   展示内容：模型名称、流式文本、耗时(ms)、消耗 Token 数预估、预估费用($)。
    *   操作按钮：**单个重试**、**中止单个**、**全部停止(Abort All)**。

### 2. 智能追问 (Follow-up)
*   每个模型卡片底部支持继续输入问题。
*   后台自动构建上下文链：`[文章内容] + [历史对话] + [新问题]`。

### 3. 高级处理流 (新引入特性)
*   **进阶 A - 多角色圆桌讨论**：允许将同一篇文章分别绑定不同的 Role Prompt（如“红队挑刺”、“狂热粉丝”）下发给多个模型，在网格布局中形成“多视角辩论”。
*   **进阶 B - 模型接力链**：允许配置串行任务（Model A -> Model B）。拦截模型 A 的结束信号，将其输出结果作为上下文，连同原文章自动发送给模型 B（如：A提炼术语 -> B润色翻译）。

## 模块三：Provider 与提示词系统 (Providers & Prompts)

### 1. 支持的 AI Provider 矩阵
每个 Provider **均可独立配置** API Key、Base URL、Model ID，支持自由开关：
*   **OpenAI** (GPT-4o, GPT-4 Turbo, o1等)
*   **Anthropic** (Claude Sonnet, Haiku, Opus)
*   **Google Gemini** (Gemini 2.0 Flash, Pro)
*   **DeepSeek** (V3, R1 等国产模型)
*   **Ollama** (本地大模型，无需 API Key)
*   **Custom (自定义)**：全面兼容任意类 OpenAI API 服务（如 OpenRouter, Groq, Moonshot等）。

### 2. Prompt 模板管理器
*   **内置 4 个经典模板**：`Summarize (中文摘要)`、`Explain Simply (简单解释)`、`Key Takeaways (关键要点)`、`Action Items (可执行建议)`。
*   **自定义模板 (Max 20 个)**：在设置页提供增、删、改功能。
*   **触发方式**：
    *   在 Side Panel 的 **ActionBar** 中提供下拉/横向滑动列表，一键选择模板并触发。
    *   支持**自定义提示词输入框**，输入后回车 (Enter) 或点击发送。

## 模块四：历史、存储与导出 (History & Export)

### 1. 本地存储与历史大盘
*   **自动落盘**：每次多模型对比/对话完成后，**自动保存**至 `chrome.storage.local`。
*   **高压实存储**：为突破扩展容量限制，必须使用 **LZ-String 压缩算法**。最多保留 **50 条**记录。
*   **快照完整性**：单条记录包含：页面标题、URL、字数、原 Prompt、每个模型的完整回答、Token数、费用、耗时。
*   **历史面板交互**：支持查看详情、点击标题跳转原页面、删除单条、**一键清空全部**。

### 2. 无缝导出体系 (支持 4 种格式)
*   **Markdown**: 生成带原标题、结构化及多模型分节的 `.md` 文件并下载。
*   **PDF**: 集成 `jsPDF` 生成带标准页码排版的 PDF 文档。
*   **Obsidian URI**: 通过 `obsidian://` 协议触发本地客户端一键创建笔记（若内容超长超过 URI 限制，自动回退复制到剪贴板并提示）。
*   **Notion**: 针对 Notion 区块特性优化的 Markdown 格式，一键复制到剪贴板，支持手动完美粘贴。

## 模块五：配置管理 (Settings 4 大核心板块)

在独立且宽敞的 Options 页面，严格划分为 4 个 Tabs：

1.  **General (通用与大盘)**：
    *   **主题切换**：明亮 (Light) / 暗黑 (Dark) / 跟随系统 (System)。
    *   **概览状态**：当前已启用的 Provider 数量。
    *   **历史统计面板**：显示总记录数、累计生成的回答总数、累计花费预估总额。
2.  **Providers (模型配置)**：
    *   上面提到的 6 大类 Provider 的独立表单（Key / URL / Model / Toggle 开关）。
3.  **Templates (模板配置)**：
    *   内置模板与自定义模板的编辑列表（增删改）。
4.  **Data (数据与维护)**：
    *   **导出配置**：将当前所有设置导出为 JSON 文件（**强制脱敏：不包含 API Key**）。
    *   **导入配置**：读取 JSON 文件还原设置。
    *   **高危操作**：彻底清空历史记录。

## 模块六：UI 体验与自动化 (UX & Automation)

### 1. 全局交互规范
*   **三维入口**：
    *   `Popup`：快捷轻量操作入口（快速触发）。
    *   `Side Panel`：主沉浸式工作区，并排对比的主视图。
    *   `Options`：全屏设置中心。
*   **设计语言**：致敬 **Obsidian 风格**。重度使用 CSS 变量控制全局，采用圆角卡片、Pill 标签样式，UI 持久化保存到 Storage。
*   **状态管理**：引入**骨架屏 (Skeleton Loading)** 缓解等待焦虑；完备的**错误边界 (Error Boundary)** 拦截报错；**离线检测**：断网时顶部弹出醒目警告 Banner。

### 2. 键盘快捷键流 (Shortcuts)
*   `summarize`：一键提取当前页并开始总结。
*   `toggle-panel`：快速开/关 Side Panel。
*   `abort-all`：紧急停止所有正在进行的网络请求。
*   `Escape (Esc)`：通用取消键（停止请求 / 关闭历史面板弹窗）。

### 3. RSS 自动化专区 (新引入后台特性)
*   在 Side Panel 提供一个独立的 `RSS Digest` 视图。
*   **Service Worker 后台运作**：定时拉取配置好的 RSS XML，发现新文章后，静默调用默认模型生成简短摘要，存入本地。
*   扩展图标通过 Badge (红点数字) 提醒用户阅读已处理好的简报。
