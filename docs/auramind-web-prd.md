# AuraMind 独立 Web 产品 PRD

- 文档版本：v1.0
- 产品名称：AuraMind
- 产品形态：独立 Web 应用
- 迁移来源：AuraMind Chrome 扩展及现有本地数据
- 文档范围：产品定位、用户流程、功能需求、数据复用、业务规则、权限与验收标准

## 1. 产品概述

### 1.1 产品定位

AuraMind 是一个以个人知识管理为核心的 AI Web 工作台，帮助用户把网页、文章、文档和 RSS 内容沉淀为可搜索、可阅读、可标注、可复习的个人知识库。

产品核心价值：

1. 快速保存：从网页或 RSS 获取干净、结构化的内容。
2. 智能理解：使用 AI 总结、问答、提取重点和生成复习材料。
3. 深度阅读：在统一阅读器中高亮、批注、收藏和回看。
4. 长期记忆：通过间隔重复安排高亮和知识卡片复习。
5. 数据可迁移：用户可以导出和同步自己的数据，不被单一平台锁定。

### 1.2 迁移目标

将当前 Chrome 扩展的核心能力迁移为独立 Web 产品，同时复用已有数据结构、业务规则和用户数据：

- 复用现有 IndexedDB/Dexie 中的内容、文档、会话、高亮、复习记录和 RSS 数据。
- 兼容现有 WebDAV、S3 及 Cloudflare D1、七牛云 Kodo 相关数据边界。
- 将扩展中的网页剪藏入口改为 Web 端导入、URL 抓取、文件上传和浏览器扩展协同入口。
- 将扩展 side panel 中的 AI 对话体验迁移为独立 Web Chat 页面，并与知识库内容打通。
- 用户迁移后可继续访问已有内容、批注、对话和复习进度，不要求重新录入。

### 1.3 产品边界

本产品包含：

- 知识库与内容管理。
- 网页、URL、文件和 RSS 内容导入。
- 内容阅读、清洗、全文搜索和标签管理。
- 高亮、批注、收藏和知识卡片。
- AI 总结、问答、对话和内容分析。
- 间隔重复复习。
- RSS 订阅与阅读队列。
- 数据同步、导入、导出和账户管理。

本产品暂不包含：

- 多人协作编辑和共享知识库。
- 面向企业的组织、团队和权限后台。
- 社交关注、评论和公开发布社区。
- AI 自动替用户执行外部系统操作。
- 付费订阅、计费和团队套餐规则。

## 2. 用户与使用场景

### 2.1 目标用户

- 研究人员：保存论文、技术文章和资料，并长期复习。
- 开发者：收藏文档、代码和方案，结合 AI 分析和检索。
- 内容工作者：管理 RSS、文章和素材，提炼观点并形成笔记。
- 学习者：将阅读高亮转换为可重复复习的知识卡片。
- 知识工作者：建立个人资料库，减少重复搜索和信息遗忘。

### 2.2 核心使用场景

1. 用户导入一个网页，系统清洗正文并生成摘要。
2. 用户阅读内容并高亮关键段落，补充个人批注。
3. 用户针对当前内容向 AI 提问，AI 基于页面上下文回答。
4. 用户将高亮加入复习队列，在到期时完成复习并记录掌握程度。
5. 用户订阅 RSS，在阅读队列中处理新文章。
6. 用户在多个设备访问同一知识库，并通过 WebDAV 或 S3 同步。
7. 用户从旧扩展导出数据，在独立 Web 产品中完成导入和恢复。

## 3. 信息架构

独立 Web 产品包含以下一级模块：

1. **首页 / 工作台**：今日复习、最近阅读、待处理内容、快捷导入。
2. **知识库**：全部内容、标签、收藏、归档和搜索结果。
3. **阅读器**：阅读正文、目录、高亮、批注和内容内 AI 操作。
4. **AI Chat**：独立对话、基于选中内容提问、会话历史和附件分析。
5. **复习**：今日待复习、复习会话、进度和历史记录。
6. **RSS**：订阅源、文章列表、未读队列和刷新状态。
7. **同步与设置**：账户、同步服务、导入、导出、模型和偏好设置。

## 4. 全局产品要求

### 4.1 账户与工作区

- 用户通过账户登录独立 Web 产品。
- 用户登录后只能访问自己拥有或被授权访问的数据。
- 用户可以查看用户名、邮箱、账户状态和同步状态。
- 用户退出后清除本地会话令牌和敏感缓存。
- 未登录用户不能读取云端知识库、对话、附件和复习数据。
- 页面需支持桌面端和移动端，移动端提供可折叠导航栏。

### 4.2 全局搜索

- 支持搜索标题、正文、摘要、标签、来源 URL、高亮和批注。
- 支持按内容类型筛选：网页、文件、RSS、笔记、对话。
- 支持按标签、收藏、阅读状态和创建时间筛选。
- 结果展示标题、摘要片段、匹配位置、来源和更新时间。
- 点击结果进入对应内容或对话，并定位到匹配上下文。
- 搜索结果需排除用户无权访问的内容。

### 4.3 通知与反馈

- 对导入、抓取、AI 生成、上传、同步和导出任务提供状态反馈。
- 成功、失败、处理中、部分成功等状态必须可区分。
- 失败提示必须说明原因，并提供可执行的重试、移除或重新配置操作。
- 不得把本地未保存、上传失败或同步失败显示为“已同步”。

## 5. 首页 / 工作台需求

### 5.1 今日概览

首页展示：

- 今日待复习数量。
- 最近新增内容。
- 最近阅读内容。
- 未读 RSS 文章数量。
- 最近的 AI 对话。
- 同步状态和最近同步时间。

### 5.2 快捷操作

- 导入 URL。
- 上传文件。
- 新建笔记。
- 新建 AI 对话。
- 开始今日复习。
- 添加 RSS 订阅。

### 5.3 待处理队列

- 展示尚未阅读、尚未整理或导入失败的内容。
- 用户可直接打开、标记已读、归档或删除。
- 导入处理中的内容展示进度和当前阶段。
- 处理失败的内容展示失败原因和重试入口。

## 6. 内容导入与网页剪藏

### 6.1 URL 导入

- 用户输入公开网页 URL 后发起导入。
- 系统抓取页面并提取标题、作者、发布时间、正文、封面图和来源 URL。
- 使用内容清洗能力移除导航、广告、脚本、评论区等非正文内容。
- 系统生成内容摘要和可选的关键词、主题标签。
- 导入任务支持处理中、成功、失败三种最终状态。
- 导入成功后创建一条知识库内容记录。
- 相同 canonical URL 或相同内容哈希的内容默认去重，并提示用户已存在记录。

### 6.2 文件导入

支持导入：

- PDF。
- TXT、Markdown、CSV、JSON。
- DOC、DOCX、XLS、XLSX。
- ZIP 中的可识别文本文件。
- 图片文件，至少支持预览；如后端支持 OCR，可提取图片文字。

功能要求：

- 支持单文件和多文件导入。
- 展示文件名、类型、大小、上传进度和处理状态。
- 文件大小、数量和类型由前后端共同校验。
- 文件导入后保留原始文件对象引用和解析后的正文。
- 文件导入失败时保留失败记录和错误原因，用户可重试或删除。

### 6.3 浏览器扩展协同

- 独立 Web 产品可接收当前 AuraMind 扩展发送的网页、选中文本和页面元数据。
- 扩展发送的数据必须经过用户授权和身份校验。
- Web 端收到剪藏请求后展示确认状态，用户可选择保存到指定标签或收藏夹。
- 当用户未登录 Web 产品时，提供登录或配对提示。
- 扩展与 Web 端使用统一内容 schema，避免同一页面产生两套不兼容数据。

### 6.4 导入后的内容属性

内容至少包含：

- 标题。
- 内容类型。
- 正文或结构化内容。
- 原始 URL。
- canonical URL。
- 作者和发布时间。
- 封面图。
- 内容哈希。
- 摘要。
- 标签。
- 收藏状态。
- 阅读状态。
- 创建时间、更新时间和最后阅读时间。
- 处理状态和错误信息。

## 7. 知识库

### 7.1 内容列表

- 默认按最近更新时间倒序展示。
- 支持列表视图和紧凑视图。
- 展示标题、内容类型、来源、标签、摘要、阅读状态和更新时间。
- 支持分页或无限滚动。
- 支持批量选择、批量加标签、收藏、归档和删除。
- 支持按“全部、未读、已读、收藏、归档”筛选。

### 7.2 内容管理

- 用户可修改标题、摘要、标签和收藏状态。
- 用户可归档内容，归档内容不出现在默认列表中但可搜索。
- 用户可删除内容；删除前需确认，并说明关联高亮、批注、复习卡片和附件的处理方式。
- 用户可复制内容链接，用于在本产品内打开对应阅读位置。
- 用户可将内容导出为 Markdown 或原始文件。

### 7.3 标签

- 用户可创建、重命名、删除标签。
- 内容支持多个标签。
- 标签删除时不删除关联内容，只移除标签关系。
- 标签列表展示关联内容数量。
- 支持从内容详情中快速添加或移除标签。

## 8. 阅读器

### 8.1 阅读体验

- 展示正文、标题、作者、来源、发布时间和内容摘要。
- 正文支持标题、列表、表格、引用、链接、代码块、图片和数学公式等结构。
- 支持目录导航，点击目录项定位到正文位置。
- 记录阅读进度和最后阅读位置。
- 支持窄版阅读布局，移动端不出现横向滚动。
- 支持调整字体大小、行高和主题；偏好设置按账户保存。

### 8.2 高亮

- 用户选中文本后显示浮动工具栏。
- 支持至少三种高亮颜色。
- 高亮记录原文、内容 ID、段落或定位信息、颜色、创建时间。
- 高亮可加入复习队列。
- 用户可删除高亮；删除前不影响原文内容。
- 页面重新打开后，高亮必须根据稳定定位信息恢复。
- 无法恢复定位时展示“原文已变化”状态，不静默移动到错误位置。

### 8.3 批注

- 用户可为高亮添加和编辑批注。
- 批注支持纯文本，最大长度由产品统一配置。
- 批注可被全局搜索。
- 批注与高亮生命周期关联；删除高亮时需要说明批注是否一并删除。
- 批注可导出到 Markdown 和 JSON。

### 8.4 阅读器内 AI

用户可基于当前内容执行：

- 总结全文。
- 提取关键观点。
- 解释选中文本。
- 翻译选中文本。
- 生成问题和答案。
- 生成复习卡片。
- 继续追问。

AI 请求需要自动携带当前内容上下文，但必须受上下文长度和用户权限限制。用户应能明确知道本次请求使用了哪一份内容。

## 9. AI Chat

### 9.1 对话工作区

- 桌面端显示对话列表和主消息区；移动端对话列表为抽屉。
- 支持新建、搜索、切换、重命名和删除对话。
- 对话列表按今天、昨天、更早分组，默认按更新时间倒序。
- 搜索匹配对话标题和消息内容。
- 新建对话后输入框自动聚焦。
- 支持 `Cmd/Ctrl + K` 新建对话。

### 9.2 模型选择

- 展示后端返回的可用模型、模型说明、推荐标记和能力标签。
- 模型切换只影响后续请求，不修改历史消息的模型记录。
- 模型能力需明确标记是否支持视觉、文件、长上下文和流式输出。
- API 密钥和模型路由不得暴露给浏览器。

### 9.3 消息发送

- 输入框最大 12,000 个字符。
- Enter 发送，Shift + Enter 换行，中文输入法组合输入期间不得误发送。
- 支持文本、图片、文档和拖拽附件。
- 无文本且无附件时禁止发送。
- 纯附件消息应以附件名称和文件内容作为请求上下文。
- 首条消息可自动生成对话标题；用户重命名后不得被覆盖。

### 9.4 AI 响应

- assistant 消息支持 SSE 或 fetch stream 流式展示。
- 生成中显示加载状态，并允许停止生成。
- 停止后保留已生成内容，消息状态标记为已停止。
- 生成失败时保留用户消息，assistant 消息显示错误和重试入口。
- 支持复制 assistant 全文、复制代码块和重新生成。
- 用户滚动离开底部时不得强制抢回滚动位置，提供回到底部操作。
- Markdown 内容必须安全清理后再渲染。

### 9.5 系统提示词

- 系统提示词按当前对话保存。
- 支持编辑、清空、取消和保存。
- 提供简洁助手、资深工程师、产品经理、苏格拉底导师等预设。
- 保存后从下一次请求生效。
- 当前对话存在系统提示词时展示状态标记。

### 9.6 Chat 附件

- 单条消息最多 6 个附件，单文件最大 20MB。
- 支持图片、PDF、TXT、Markdown、CSV、DOC、DOCX、XLS、XLSX、ZIP、JSON，最终以服务端白名单为准。
- 上传卡片展示文件名、大小、进度、完成状态和移除操作。
- 图片支持大图预览和下载原图。
- 非图片附件展示文件类型图标、名称和大小。
- 发送失败时不得丢失用户输入或附件引用。

## 10. RSS 阅读器

### 10.1 订阅源管理

- 用户可通过 RSS/Atom URL 添加订阅源。
- 系统自动读取标题、站点名称、图标、描述和更新时间。
- 支持编辑订阅源名称、刷新频率和所属标签。
- 支持暂停、恢复和删除订阅源。
- 删除订阅源时可选择保留或删除已导入文章。
- 自动发现网页中的 RSS/Atom 地址时提供添加入口。

### 10.2 文章处理

- 按订阅源展示文章标题、摘要、作者、发布时间、封面图和原文链接。
- 支持未读、已读、收藏、归档和导入知识库。
- 文章导入知识库时复用 URL 抓取、正文清洗、去重和标签能力。
- 定时刷新订阅源，支持手动刷新。
- 使用内容哈希或稳定文章 ID 去重。
- 刷新失败时展示订阅源级错误状态，不影响其他订阅源。

### 10.3 阅读队列

- 支持将文章加入稍后阅读。
- 支持批量标记已读、收藏和归档。
- 支持按订阅源、时间、未读和收藏筛选。
- 用户打开文章后可直接进入阅读器和 AI 操作。

## 11. 间隔重复复习

### 11.1 复习对象

复习对象来源包括：

- 阅读器中的高亮。
- 用户手动创建的知识卡片。
- AI 根据文章或对话生成的问答卡片。
- 用户从批注或摘要中手动加入的内容。

### 11.2 复习流程

- 首页展示今日到期数量。
- 用户进入复习会话后逐条查看问题或内容片段。
- 用户可显示答案或原文。
- 用户反馈掌握程度，至少支持“忘记、困难、良好、简单”。
- 系统根据 SM-2 规则更新下次复习时间、间隔、难度和复习次数。
- 复习完成后展示本次完成数量和下一次到期时间。
- 用户可暂停并稍后继续，已完成记录不得重复提交。

### 11.3 复习管理

- 展示全部复习卡片、到期卡片、已暂停卡片和复习历史。
- 支持从卡片回到原文位置。
- 支持编辑卡片正面、答案、标签和来源。
- 删除来源高亮时，应明确提示关联复习卡片的处理方式。
- 支持按标签和来源筛选复习卡片。

## 12. 数据复用与迁移

### 12.1 现有数据复用原则

独立 Web 产品应优先兼容现有扩展数据，不要求用户通过复制粘贴恢复内容。

需要复用的数据包括：

- 内容记录和正文。
- 网页 URL、来源和内容哈希。
- 文件元数据及对象存储引用。
- 摘要、关键词和标签关系。
- 高亮、颜色、原文定位和批注。
- 复习卡片、复习间隔、难度、到期时间和历史记录。
- RSS 订阅源、文章记录、阅读状态和去重信息。
- AI 对话、消息、模型记录、系统提示词和附件元数据。
- 用户偏好、收藏状态、归档状态和最后阅读位置。

### 12.2 数据来源兼容

产品需支持以下数据来源的导入或迁移：

1. 扩展本地 IndexedDB/Dexie 数据。
2. 扩展生成的 JSON、Markdown 和 ZIP 导出包。
3. 现有 WebDAV 同步目录。
4. 现有 S3 兼容对象存储中的附件和数据文件。
5. 后续服务端数据库中的 D1 会话元数据。

### 12.3 本地数据迁移

- 扩展提供迁移入口，用户确认后导出带版本号的数据包。
- Web 产品提供导入入口，支持选择 JSON 或 ZIP 文件。
- 导入前展示数据统计：内容数、对话数、高亮数、复习卡片数、RSS 源数和附件大小。
- 导入过程支持校验、预览、执行、完成和失败状态。
- 导入过程中遇到重复数据时按稳定 ID、canonical URL 或内容哈希去重。
- 用户可选择覆盖、跳过或保留重复记录；默认不删除 Web 端已有数据。
- 导入失败应支持重新执行，不产生半条可见数据或孤立附件。
- 导入完成后报告新增、更新、跳过和失败数量。

### 12.4 数据 schema

导出文件必须包含版本号和导出时间。推荐结构：

```ts
interface AuraMindExport {
  version: string;
  exportedAt: string;
  account?: {
    id?: string;
    email?: string;
  };
  contents: Content[];
  highlights: Highlight[];
  annotations: Annotation[];
  reviewCards: ReviewCard[];
  reviewLogs: ReviewLog[];
  feeds: Feed[];
  feedItems: FeedItem[];
  conversations: Conversation[];
  attachments: Attachment[];
  settings?: UserSettings;
}
```

字段迁移要求：

- 日期统一转换为 ISO 8601 UTC。
- 原有时间戳、UUID、对象 Key 和内容哈希尽量保持不变。
- 原有字段无法映射时保留在 `metadata` 中，不静默丢弃。
- 删除、归档和已读状态必须保留。
- 本地 `blob:` URL、临时 File 对象和访问令牌不得写入导出文件。
- 附件通过稳定 `objectKey` 或附件 ID 关联，不保存短期下载 URL。

### 12.5 同步

- 用户可配置 WebDAV 或 S3 兼容同步。
- 支持手动同步和按策略自动同步。
- 同步前展示上次同步时间和当前状态。
- 支持上传、下载和双向同步。
- 冲突按记录 ID 和 `updatedAt` 检测，不覆盖未确认的本地修改。
- 冲突记录需要展示本地版本、云端版本和用户选择入口。
- 同步失败可重试，并保留本地未同步数据。
- 附件和结构化数据必须分别处理，不能因单个大附件失败而丢失会话元数据。
- 同步配置中的密码、Token 和密钥应加密存储，不进入普通导出文件。

## 13. 导出与备份

### 13.1 导出范围

- 当前内容。
- 当前对话。
- 当前复习卡片。
- 全部知识库数据。
- 全部数据及原始附件。

### 13.2 导出格式

- JSON：适合程序迁移，包含完整结构化数据。
- Markdown：适合人类阅读、知识库归档和外部笔记工具。
- ZIP：包含 JSON、Markdown 和可获取的原始附件。

### 13.3 导出规则

- 导出文件名清理系统非法字符并限制长度。
- 导出大数据量时使用后台任务和临时下载地址。
- 下载地址使用短期签名 URL，并在过期后失效。
- 导出过程中展示进度、成功结果和失败原因。
- 导出的数据不得包含 API 密钥、登录令牌和内部服务凭证。

## 14. 权限、安全与隐私

1. 所有内容、消息、附件和复习数据接口都必须校验用户身份和资源归属。
2. API 密钥只由服务端管理，浏览器端不得直接保存供应商密钥。
3. Markdown、富文本、外部链接和导入内容必须经过安全清理。
4. 文件上传由服务端重新校验 MIME、扩展名、大小和恶意内容风险。
5. 附件访问使用短期签名地址，禁止公开暴露私有对象。
6. AI 请求只能携带当前用户有权访问的内容。
7. 用户删除数据后，应同步清理正文、索引、附件引用、高亮和复习关联数据。
8. 账户注销前必须提供数据导出入口，并明确注销后的数据删除范围。
9. 日志不得记录完整正文、批注、系统提示词、附件内容或认证凭证。
10. 产品应提供隐私说明，明确数据存储、AI 处理、同步和删除规则。

## 15. 业务规则

### 15.1 内容去重

- 优先使用 canonical URL 去重。
- 无 URL 内容使用内容哈希去重。
- 内容重新抓取后，如正文发生变化，应创建版本或更新记录，并保留用户高亮定位信息。
- 去重命中时默认不创建重复记录，允许用户查看已有内容。

### 15.2 删除与关联数据

- 删除内容前必须告知关联的高亮、批注、复习卡片和附件数量。
- 用户可选择同时删除关联数据，或保留可独立存在的复习卡片。
- 删除对话需删除消息引用，但已被其他数据引用的附件必须使用引用计数或软删除策略。
- 回收站或可恢复删除不属于首版必需能力，但删除策略必须明确。

### 15.3 内容状态

内容至少支持：

- 未读。
- 阅读中。
- 已读。
- 收藏。
- 归档。
- 处理中。
- 处理失败。

状态之间可以并存，例如“已读 + 收藏”，不能用单一字段覆盖所有状态。

### 15.4 AI 生成内容

- AI 生成的摘要、标签、卡片和回答必须记录来源内容、模型和生成时间。
- AI 结果允许用户编辑，编辑后不得被下一次自动生成无提示覆盖。
- AI 生成失败不影响原始内容、用户高亮和批注。
- 产品界面必须提示 AI 内容可能不准确，重要信息需要用户核验。

## 16. 功能验收标准

### 16.1 内容与知识库

- 用户可通过 URL 导入网页，并获得清洗后的正文、元数据和处理状态。
- 用户可上传支持的文件，并在处理完成后阅读或搜索内容。
- 用户可搜索标题、正文、标签、高亮、批注和对话。
- 用户可修改标签、收藏、阅读状态、归档状态并刷新后保持。
- 重复 URL 或内容不会无提示地产生重复记录。

### 16.2 阅读与知识沉淀

- 用户可以正常阅读内容、查看目录、记录进度。
- 用户选中文本可以创建高亮、选择颜色和添加批注。
- 页面重新打开后高亮能恢复到正确文本；正文变化时有明确异常提示。
- 用户可以把高亮或 AI 生成内容加入复习队列。

### 16.3 AI Chat

- 用户可以创建、搜索、切换、重命名、删除对话。
- 用户可以选择模型并发送文本和附件。
- assistant 能以流式方式返回内容，用户可以停止、复制和重新生成。
- Markdown 和代码块安全渲染。
- 网络错误、模型错误、上传失败不会丢失用户消息。

### 16.4 RSS

- 用户可以添加 RSS/Atom 订阅源并读取文章列表。
- 系统能够刷新订阅源并根据稳定 ID 或内容哈希去重。
- 用户可以标记已读、收藏、归档和导入知识库。
- 单个订阅源失败不影响其他订阅源。

### 16.5 复习

- 首页和复习页准确展示到期卡片。
- 用户可以完成一轮复习并选择掌握程度。
- SM-2 相关间隔、难度、到期时间和复习历史能正确更新。
- 用户可以从复习卡片回到原文位置。

### 16.6 数据迁移与同步

- 扩展导出的数据包可在 Web 产品中导入。
- 导入前展示统计，导入后报告新增、更新、跳过和失败数量。
- 重复导入不会产生重复内容、消息、卡片或 RSS 文章。
- 原有 ID、时间、标签、批注、高亮和复习进度可继续使用。
- WebDAV/S3 同步失败时本地数据不丢失，恢复连接后可以重试。
- JSON、Markdown、ZIP 导出内容可读取，附件引用关系保持正确。

### 16.7 响应式与可用性

- 桌面端和宽度约 375px 的移动端无关键内容遮挡。
- 移动端导航、输入框、阅读器、弹窗和图片预览均可操作。
- 键盘用户可访问主要按钮、输入控件、菜单和弹窗。
- 所有异步操作都有明确的处理中、成功和失败反馈。

## 17. 待确认产品决策

1. 独立 Web 产品是否继续与 Chrome 扩展共用同一账户和后端 API。
2. 现有 IndexedDB/Dexie schema 的正式版本号和迁移脚本位置。
3. WebDAV、S3、D1、Kodo 中哪些是首版正式支持的数据源。
4. 是否允许离线使用；若允许，Web 端采用 IndexedDB 缓存还是仅做 PWA 离线队列。
5. URL 抓取、文件解析、OCR 和 RSS 刷新由现有服务承担还是新增服务。
6. AI 模型列表、视觉输入、文件解析和上下文长度能力由哪个服务提供。
7. 删除内容、删除附件和保留复习卡片之间的最终关联策略。
8. 是否需要提供 Web 产品向 Chrome 扩展的反向同步，以及同步冲突的用户界面。
