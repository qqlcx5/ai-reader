# AuraMind 独立 Web 产品需求文档

- 文档版本：v0.2
- 来源：当前 AuraMind 扩展代码、`README.md` 与设计稿 [`chat.html`](../chat.html)
- 目标产品：AuraMind Web
- 产品形态：独立 Web 应用，复用现有业务能力，但不依赖 Chrome side panel、当前标签页和扩展专属 API
- 当前状态：现有项目是 Chrome MV3 扩展；本文件定义其完整 Web 化重做需求

## 1. 目标与范围

### 1.1 产品目标

在独立 Web 端复刻并扩展 AuraMind 当前项目的全部核心能力：用户可以采集网页、阅读和标注内容，建立可搜索的个人知识库，使用 AI 分析和对话，并通过 RSS、间隔复习、导出和同步形成可迁移的知识工作流。

Web 端必须共享稳定的数据模型和业务服务边界，不能仅复制 side panel 的视觉层。所有原本依赖浏览器扩展的能力都必须在 Web 端有对应入口、权限说明和失败反馈。

### 1.2 本期范围

#### A. Web 应用基础

- 独立登录、登出、账户信息和权限控制。
- 桌面端和移动端响应式布局。
- 全局导航、页面历史、通知、加载、空状态和错误状态。
- IndexedDB 本地缓存与服务端数据同步策略。

#### B. 网页采集与阅读

- 通过输入 URL、书签导入、浏览器扩展桥接或浏览器分享入口采集网页。
- 清理正文、标题、作者、站点、发布时间、摘要、原始 URL 和规范 URL。
- 阅读器展示 Markdown/HTML 正文、目录、代码、表格、数学公式和媒体。
- 阅读进度、已读状态、最近打开、原始页面信息和重新采集。
- 高亮文本、选择颜色、添加批注、编辑和删除高亮。

#### C. 记忆库

- 文档列表、全文搜索、排序、状态筛选、站点筛选、标签筛选和日期筛选。
- 文档详情、标签、集合/文件夹、批量选择、批量删除和批量导出。
- 文档关联对话、收藏内容和阅读状态。

#### D. AI 能力

- 当前文档上下文问答和独立 AI 对话。
- 多模型配置、默认模型、模型启停、模型连通性测试和模型参数。
- 文本、代码、网页上下文和附件输入。
- 流式生成、停止、重试、重新生成、复制、编辑、删除和对话分支。
- AI 摘要、结构化分析、批量分析任务和分析结果。
- Token 用量、请求耗时、模型成本和用量统计。
- 全局系统提示词、会话提示词和提示词模板。

#### E. RSS 与复习

- RSS/Atom 订阅添加、编辑、删除、刷新、自动刷新和去重。
- Feed 条目列表、阅读状态、原文打开和转入知识库。
- 基于 SM-2 的复习队列、复习评分、到期计划和复习统计。

#### F. 数据迁移与同步

- 当前对话、全部对话、文档和附件导出。
- JSON、Markdown、ZIP 和标准化数据版本。
- WebDAV 和 S3 兼容存储同步，包括坚果云、Nextcloud、Cloudflare R2、AWS S3、MinIO 等。
- 同步状态、最近同步时间、冲突处理、失败重试和手动同步。

### 1.3 暂不包含

- 多人协作、共享知识库、团队权限和评论。
- 语音输入、语音输出和实时通话。
- 图片生成、视频生成和通用多媒体创作。
- 企业级审计、计费、组织管理和管理员后台。
- 在浏览器中绕过网站限制抓取受登录、付费墙或跨域策略保护的内容。
- 完整的离线 AI 推理；离线模式只保证已缓存数据可读写，AI 请求需要可用模型服务。

## 2. 用户与核心流程

### 2.1 目标用户

- 需要保存、阅读、检索和复习大量网页资料的研究者和开发者。
- 需要使用 AI 分析网页、文档、代码和技术方案的知识工作者。
- 需要跨设备访问，并且不希望被单一平台锁定的用户。

### 2.2 首次使用流程

1. 用户打开 Web 端并完成登录或选择本地优先模式。
2. 系统初始化本地数据库、模型配置、同步配置和搜索索引。
3. 用户可以输入 URL 采集第一篇文档，或导入已有数据。
4. 采集完成后进入阅读器，可阅读、标注、添加标签、发起 AI 对话。
5. 系统将文档加入记忆库，并根据设置进入分析或复习流程。

### 2.3 网页采集流程

1. 用户输入 URL、使用浏览器扩展发送当前页面，或从 RSS 条目转入采集。
2. 系统展示采集状态：排队、抓取、解析、保存、失败。
3. 系统提取正文和元数据，并计算内容哈希用于去重。
4. 用户确认标题、标签、集合和是否启动 AI 分析。
5. 文档保存到记忆库，用户可进入阅读器、AI 对话或复习队列。

### 2.4 阅读与标注流程

1. 用户从记忆库打开文档。
2. 阅读器恢复上次阅读位置并更新最近打开时间。
3. 用户选择正文内容，创建高亮并选择颜色。
4. 用户可以为高亮添加批注、编辑、删除或转为 AI 问题。
5. 用户可在当前文档上下文中开始对话。

### 2.5 AI 对话流程

1. 用户在文档详情或全局工作区创建对话。
2. 用户选择一个或多个已配置模型，确认是否附带当前文档上下文。
3. 用户发送文本、代码或附件。
4. 系统上传附件、持久化 user 消息并创建 assistant 生成任务。
5. 系统通过流式事件展示结果，支持停止、失败重试和重新生成。
6. 对话保存到当前文档或独立会话空间，并可导出或创建分支。

### 2.6 复习流程

1. 系统根据文档、高亮或 AI 生成的复习项目计算到期时间。
2. 用户进入复习队列，先查看问题或内容，再选择记得程度。
3. 系统根据 SM-2 更新间隔、难度、重复次数和下一次复习时间。
4. 用户可以查看今日完成量、连续天数和待复习数量。

## 3. 功能需求

### 3.1 Web 应用基础与身份

| 编号 | 需求 | 优先级 |
|---|---|---|
| W-01 | Web 端提供登录、注销、会话过期和账户状态处理；本地优先模式必须明确提示数据仅保存在当前浏览器。 | P0 |
| W-02 | 首次加载初始化本地数据库、Pinia 状态、搜索索引、模型配置和应用设置。 | P0 |
| W-03 | 支持桌面端、平板端和 375px 左右移动端；导航在小屏幕下折叠为抽屉或底部导航。 | P0 |

| A-03 | 展示会话元数据服务和附件存储服务的健康状态。 | P1 |
| A-04 | “退出登录”必须调用真实认证退出；演示模式提示不能作为生产行为。 | P0 |
| A-05 | 数据迁移说明应与实际导出能力一致，不得声称尚未实现的 SQLite/S3 下载能力可用。 | P0 |

## 4. 数据模型

Web 端需要将当前扩展中的本地实体提升为可同步的稳定 schema。下面是最小模型，实际字段应以现有 `types/` 为基础统一命名。

```ts
interface User { id: string; email: string; name?: string; createdAt: string }
interface Document {
  id: string; url: string; canonicalUrl?: string; title: string; markdown: string;
  contentHash: string; siteName?: string; author?: string; description?: string;
  publishedAt?: string; capturedAt: string; updatedAt: string; lastOpenedAt?: string;
  readProgress: number; readAt?: string; tags: string[]; highlights: Highlight[];
}
interface Highlight {
  id: string; documentId: string; quote: string; note?: string; color: string;
  locator?: string; createdAt: string; updatedAt: string;
}
interface Collection { id: string; name: string; createdAt: string; updatedAt: string; documentIds: string[] }
interface Conversation { id: string; documentId?: string; title: string; messages: Message[]; createdAt: string; updatedAt: string }
interface ReviewItem { id: string; sourceType: 'document' | 'highlight' | 'note'; sourceId: string; dueAt: string; interval: number; easeFactor: number; repetitions: number }
interface Feed { id: string; url: string; title: string; siteUrl?: string; lastFetchedAt?: string; error?: string }
interface FeedItem { id: string; feedId: string; guid: string; title: string; url: string; content?: string; publishedAt?: string; isRead: boolean }
```

数据层还需要覆盖：Attachment、AnalysisJob、UsageRecord、PromptTemplate、ModelConfig、ReviewLog、SyncConfig、SyncCursor、ConflictRecord 和 ExportManifest。

所有实体必须包含稳定 ID、创建/更新时间和同步元数据（如 `updatedAt`、删除标记或版本号）。本地 IndexedDB 与服务端数据库的字段映射必须文档化。

### 4.1 数据分层

- 内容层：Document、Feed、FeedItem、Attachment。
- 组织层：Collection、Tag、Highlight。
- AI 层：Conversation、Message、AnalysisJob、UsageRecord、PromptTemplate、ModelConfig。
- 学习层：ReviewItem、ReviewLog、ReviewSchedule。
- 同步层：SyncConfig、SyncCursor、ConflictRecord、ExportManifest。

### 4.2 数据保留与删除

- 删除文档时明确显示会级联删除的对话、分析任务、集合引用和复习项目。
- 云端删除支持软删除和同步传播，避免其他设备重新恢复已删数据。
- 附件对象与消息引用分离管理，只有没有引用且超过保留期后才物理删除。

### 4.3 Conversation

```ts
interface Conversation {
  id: string;
  title: string;
  createdAt: string;
  updatedAt: string;
  modelId: string;
  systemPrompt: string;
  messages: Message[];
}
```

约束：

- `id` 使用服务端生成的不可变 ID。
- `title` 最大 60 个字符；首条消息后可自动生成，用户重命名后不得被自动标题覆盖。
- 时间统一使用 ISO 8601 UTC。
- `updatedAt` 在新消息、重命名、模型切换、提示词保存等会话变更后更新。

### 4.4 Message

```ts
interface Message {
  id: string;
  conversationId: string;
  role: "user" | "assistant" | "system";
  content: string;
  modelId?: string;
  status: "pending" | "streaming" | "completed" | "stopped" | "failed";
  createdAt: string;
  updatedAt?: string;
  attachments: Attachment[];
  errorCode?: string;
  errorMessage?: string;
}
```

### 4.5 Attachment

```ts
interface Attachment {
  id: string;
  messageId?: string;
  name: string;
  size: number;
  mimeType: string;
  objectKey?: string;
  uploadStatus: "uploading" | "ready" | "failed";
  createdAt: string;
}
```

注意：浏览器 `blob:` URL 和原始 `File` 只用于本次页面会话，不能作为持久化数据或导出数据中的云端引用。

## 5. 后端接口建议

接口名称可按现有服务层调整，以下定义 Web 产品行为契约。除本地优先模式外，所有接口都必须按用户隔离数据。

### 5.1 Web 应用与内容

| 接口 | 方法 | 作用 |
|---|---|---|
| `/api/auth/session` | GET | 获取当前 Web 登录态和账户信息。 |
| `/api/auth/logout` | POST | 注销当前会话。 |
| `/api/capture` | POST | 提交 URL 采集任务。 |
| `/api/capture/:id` | GET | 获取采集任务状态和结果。 |
| `/api/documents` | GET/POST | 分页搜索或创建文档。 |
| `/api/documents/:id` | GET/PATCH/DELETE | 获取、更新、删除文档。 |
| `/api/documents/:id/highlights` | POST/PATCH/DELETE | 管理高亮和批注。 |
| `/api/collections` | GET/POST/PATCH/DELETE | 管理集合。 |
| `/api/feeds` | GET/POST/PATCH/DELETE | 管理 RSS/Atom 订阅。 |
| `/api/feeds/:id/refresh` | POST | 刷新订阅并返回新增条目。 |
| `/api/review/queue` | GET | 获取到期复习项目。 |
| `/api/review/items/:id/grade` | POST | 提交复习评分并更新 SM-2 状态。 |

### 5.2 AI、文件、同步与导出

| 接口 | 方法 | 作用 |
|---|---|---|
| `/api/chat/models` | GET | 返回模型、Provider 和 capability。 |
| `/api/models` | GET/POST/PATCH/DELETE | 管理用户模型配置。 |
| `/api/conversations` | GET/POST | 搜索和创建会话。 |
| `/api/conversations/:id` | GET/PATCH/DELETE | 管理会话。 |
| `/api/conversations/:id/messages` | GET/POST | 获取历史和发送消息。 |
| `/api/chat/stream` | GET/POST | 通过 SSE 或 fetch stream 返回增量内容。 |
| `/api/analysis/jobs` | GET/POST | 创建和查询 AI 分析任务。 |

| `/api/files/presign` | POST | 获取附件上传地址和对象元数据。 |

| `/api/usage` | GET | 获取 Token、成本和请求统计。 |

旧的聊天接口可作为 `/api/chat/*` 的兼容实现，但不能让 Web 页面直接依赖供应商 API 密钥。

### 5.3 流式响应事件

建议使用 SSE，至少支持：

```text
message.started   { messageId, modelId }
message.delta     { messageId, text }
message.completed { messageId, usage }
message.failed    { messageId, code, message }
message.stopped   { messageId }
```

客户端必须按 `messageId` 处理事件，支持网络中断、重复事件和用户主动停止，不能仅依赖单一全局计时器。

### 5.4 Web 与扩展桥接

浏览器扩展只作为采集入口和可选快捷入口，不作为 Web 端运行前提。桥接协议至少支持：

- 扩展将当前 URL、页面标题和可选正文发送到 Web 端。
- Web 端返回采集任务 ID 和处理结果。
- 用户未登录或 Web 端不可用时，扩展保留本地队列并在下次连接时重试。
- 桥接请求必须校验来源、用户身份和一次性 token。

## 6. 状态与错误处理

### 6.1 页面状态

- 初始化：正在加载模型、对话和账户状态。
- 空列表：没有任何对话时展示可直接开始的空状态。
- 搜索无结果：显示无匹配提示。
- 加载更多：对话和消息分页加载时显示局部 loading。
- 保存中：标题、模型、系统提示词更新时提供保存状态。
- 生成中：输入区禁用发送，允许停止。
- 生成完成：显示复制、重新生成操作。
- 生成失败：保留 user 消息，assistant 消息标记失败，提供重试。
- 上传失败：保留错误文件卡片，允许移除并重新上传。
- 未登录/会话过期：跳转登录或显示登录提示，不展示伪造的同步成功状态。

### 6.2 必须处理的错误

- 网络断开或 SSE 中断。
- 模型不可用、额度不足或服务端超时。
- 文件类型、大小、数量超限。
- 上传成功但消息发送失败。
- 删除或重命名并发冲突。
- 导出数据量过大或附件无法读取。
- 当前会话已被其他端删除。

## 7. 安全与隐私

1. API 密钥只保存在服务端或受控密钥管理系统，不进入浏览器代码和导出文件。
2. Markdown 渲染必须使用 DOMPurify 或等效策略清理 HTML、脚本和危险链接。
3. 服务端必须再次校验文件 MIME、扩展名、文件大小和病毒/恶意内容风险；不能信任浏览器校验。
4. 所有会话、消息和附件接口必须校验当前账户权限，禁止通过 ID 越权读取。
5. 下载地址使用短期签名 URL；对象 Key 不直接暴露敏感路径。
6. 导出文件包含用户数据，应设置合理的过期时间并避免写入服务端永久临时文件。
7. 对消息长度、附件数量、请求频率和模型上下文长度设置服务端限制。

## 8. 验收标准

### 8.1 P0 验收

- 用户可登录 Web 端，刷新后登录态、本地缓存和权限状态正确。
- 用户可通过 URL 采集网页，采集结果可进入阅读器和记忆库；失败可重试。
- 阅读器可恢复进度，正文高亮和批注刷新后仍存在。
- 记忆库可搜索、筛选、排序、创建集合、批量操作和删除文档。
- 用户可在文档上下文中发送 AI 消息，并看到真实流式回复；停止、失败和重试状态正确。
- 模型配置、提示词、会话、消息、文档和设置都能持久化，不能依赖设计稿示例数据。
- RSS 可添加、刷新、去重，条目可标记已读并转入记忆库。
- 复习队列可生成，评分后 SM-2 状态和下一次到期时间正确。
- JSON/Markdown 导出可解析，导出内容包含文档、对话、消息、标签、高亮和附件元数据。
- 关键操作失败不丢数据、不显示虚假的“已同步/已保存”，且移动端无关键控件遮挡。

### 8.2 P1 验收

- ZIP 包含可读取的 JSON、Markdown 和可获取的附件。
- 批量 AI 分析支持进度、失败项和重试。
- WebDAV/S3 同步支持增量同步、冲突提示和失败重试。
- 账户、模型、用量、订阅和复习统计页面来自真实持久化数据。
- 扩展发送当前网页到 Web 端的桥接流程可用。

## 9. 产品约束

- Web 端必须独立运行，核心流程不能依赖 Chrome side panel 或当前浏览器标签页。
- 浏览器扩展作为可选采集入口，通过安全桥接将 URL、页面内容或采集任务发送到 Web 端。
- 本地 IndexedDB、服务端数据、WebDAV/S3 同步数据必须使用统一的数据模型和版本号。
- AI 请求、文件上传、同步、导出和采集都必须有明确的进行中、成功、失败和重试状态。
- 所有用户数据必须按账户隔离；本地优先模式必须明确数据存储位置和跨设备限制。
- 导出文件不得包含 API 密钥、访问令牌、内部鉴权信息或未授权用户数据。
- Web 端必须支持桌面端和移动端，关键页面不得出现横向溢出或不可操作控件。
- 采集、阅读、记忆库、AI 对话、批量分析、RSS、复习、同步、模型和设置必须可从全局导航访问。

## 10. 需求范围总结

AuraMind Web 是一个独立的个人知识工作台，包含以下完整能力域：

1. 网页采集：从 URL、扩展桥接、浏览器分享和 RSS 条目获取网页内容。
2. 阅读器：阅读清洗后的正文，保存进度，支持高亮和批注。
3. 记忆库：搜索、筛选、排序、标签、集合、批量操作和文档管理。
4. AI 对话：基于文档上下文或独立上下文进行单模型/多模型对话。
5. 批量分析：对多个文档创建、执行、查看和重试 AI 分析任务。
6. RSS：管理订阅、刷新条目、去重、标记阅读并转入记忆库。
7. 复习：基于文档和高亮建立复习项目，使用 SM-2 计算复习计划。
8. 同步：使用 WebDAV/S3 进行跨设备数据同步，处理状态、冲突和失败重试。
9. 模型：配置 Provider、模型、参数、默认模型、启停状态、连通性和用量。
10. 设置：管理账户、全局提示词、上下文、采集、分析、同步、导出和存储设置。
11. 数据迁移：导出和导入结构化数据、Markdown、ZIP 及附件。

以上能力构成独立 Web 产品的完整需求范围。
