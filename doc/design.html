高吞吐避免主线程崩溃核心设计

为支撑百万 Token 原生正文和上万条聊天快照高速浏览，本系统在工程实现上严格限制了以下红线：

① 虚拟滚屏回收 (Virtual Scrolling)

历史列表采用动态节点回收技术。即便本地缓存万条记录，DOM 树内存始终限制渲染视口仅可见的 20 余个常驻节点。

② 主副表秒开分离设计 (Dexie.js Lazy Load)

主表 Conversations 仅存放轻量元数据，检索耗时低于 5ms。点击历史节点时，才根据 ID 懒加载携带百万 Token payload 的副表 Messages 进入内存。

③ Web Worker 隔离计算线程

全文关键字检索及批量 Zip 压缩归档打包，均注册原生 Web Worker 进行隔离运行，规避引起 UI 线程的丢帧和假死卡顿。

④ rAF SSE 节流重绘降频

由于 SSE 解包极快，禁止每个 Chunk 回调执行 DOM 解析。利用 requestAnimationFrame 设定约 16ms 缓存渲染周期，确保帧率 $\ge 45\text{fps}$。
