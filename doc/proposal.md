# 产品需求文档 (PRD)：ReadChat Clipper

## 1. 产品概述
**1.1 产品定位**
一款主打“一页一会话（Page-Isolated Chat）”的浏览器扩展。它能够精准提取当前网页的正文内容作为背景知识，让用户通过调用大模型（LLM）与当前网页进行深度对话。所有提取的内容和对话记录均与特定网页绑定，持久化保存在本地，并支持跨设备/跨浏览器的全量备份与恢复。

**1.2 核心价值**
*   **专注阅读与思考：** 借鉴 Obsidian Clipper 的提取算法，去广告、去干扰，只保留核心正文。
*   **上下文绝对隔离：** 页面 A 的对话绝不会污染页面 B，符合人类基于特定文章进行批注和探讨的认知习惯。
*   **数据资产私有化：** 对话不再阅后即焚，不仅保留文章快照，还保留基于文章的思想碰撞（对话），并支持完全导出。

---

## 2. 核心功能需求

### 2.1 智能正文提取 (基于 Obsidian-Clipper 逻辑)
*   **自动解析：** 当用户在某网页唤出侧边栏时，自动调用 Mozilla Readability 算法（或类似的高效算法）提取网页标题、作者、发布时间、正文内容（Markdown 格式）。
*   **元数据保存：** 提取时自动记录当前页面的 URL、Favicon、抓取时间。

### 2.2 独立页面对话系统 (Page-Isolated Chat)
*   **URL 绑定机制：** 以网页 URL（去参数后的净网址或 Hash 后的 ID）作为唯一主键。
*   **自动 Context 注入：** 将提取到的 Markdown 正文作为 Context 注入给大模型，用户无需手动粘贴文章。
*   **状态恢复：** 用户关闭侧边栏或关闭网页后，再次打开同一 URL 时，自动加载该页面的历史对话记录。

### 2.3 高级 AI 对话体验 (借鉴 Cherry Studio)
*   **多模型支持：** 支持配置自定义 API (OpenAI, Anthropic, Gemini, DeepSeek, 各种中转 API)。
*   **流式输出与渲染：** 支持打字机效果的流式输出，支持复杂的 Markdown 渲染（表格、代码块高亮、数学公式 LaTeX）。
*   **快捷指令 (Prompt 模板)：** 预设如“总结摘要”、“解释关键概念”、“提取核心观点”、“翻译成中文”等一键操作按钮。
*   **对话管理：** 支持重试 (Regenerate)、编辑用户消息、删除单条对话。

### 2.4 数据历史与资产管理 (Library)
*   **历史记录面板：** 提供一个独立的“阅读库”页面（类似书签管理器），按时间倒序或域名分类展示所有抓取并对话过的页面。
*   **快照查看：** 在阅读库中，用户可以同时查看当时的**文章正文快照**和**对话记录**（即使原网页已失效被删除，本地数据依然可用）。
*   **搜索功能：** 支持全文检索（搜索文章标题、正文或对话记录中的关键词）。

### 2.5 跨设备备份与全量恢复
*   **全量导出：** 将所有的网页元数据、正文快照、对话记录打包生成一个 `.json` 或 `.zip` 备份文件下载到本地。
*   **全量导入与合并：** 支持在新浏览器/新电脑上导入备份文件。支持“覆盖合并”和“跳过重复项”策略。
*   **零丢失承诺：** 确保导出的数据格式标准，不仅用于扩展恢复，也可被脚本解析转换为 Obsidian/Notion 格式。

## 3. UI / UX 交互设计

**3.1 扩展主要入口**
*   **侧边栏 (Side Panel)：** 推荐采用 Chrome Side Panel API 开发，不遮挡原网页，边看边聊。
*   **右键菜单 (Context Menu)：** “将选中文本添加到当前页会话”。

**3.2 界面布局划分**
*   **顶部 (Header)：** 模型切换下拉框、页面提取状态指示器（显示：已提取 2300 字）、设置按钮。
*   **主体 (Chat View)：** 类似 Cherry Studio 的气泡对话流。首条消息固定为系统生成的“页面摘要”卡片，可点击展开查看提取的原文章。
*   **底部 (Input Box)：** 多行输入框，发送按钮，停止生成按钮，快捷 Prompt 按钮排布区。

**3.3 独立管理页 (Options/History Page)**
*   类似浏览器历史记录的宽屏大面板。
*   左侧列表：网页标题、抓取时间。
*   右侧分屏展示：Tab 1 提取的正文，Tab 2 对话历史。

---

## 4. 底层数据结构设计

为了满足大量文本和持久化存储需求，**弃用**容易触发配额限制的 `chrome.storage.local`，**强制使用 IndexedDB** 作为本地数据库。

**核心表结构 (PageRecord)：**
```json
{
  "id": "hash(url)",                 // 唯一ID
  "url": "https://example.com/art",  // 原始链接
  "title": "网页标题",               // 页面标题
  "favicon": "https://...",          // 图标
  "timestamp": 1715000000,           // 抓取/最后对话时间
  "content": {
    "rawText": "...",                // 提取的原文 (Markdown格式)
    "wordCount": 1500
  },
  "chatHistory": [
    {
      "role": "user",
      "content": "请总结这篇文章的三个核心论点",
      "timestamp": 1715000100
    },
    {
      "role": "assistant",
      "model": "gpt-4o",
      "content": "核心论点如下：\n1. ...",
      "timestamp": 1715000120
    }
  ]
}
```
